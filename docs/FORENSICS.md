# 会话日志分析记录

这是一份历史数据附录，不代表当前版本的 live 结果。数据来自用户提供的两次 DSH 会话：

| 会话 | 文件规模 | 运行时间 | 结果 |
| --- | ---: | ---: | --- |
| `b2000b20` | 2878 行 / 8.4 MB | 约 2.8 小时 | 78 题中完成 42 题，排名第 1 |
| `dc721e9d` | 1635 行 / 4.9 MB | 约 31.6 分钟 | 用于短时行为对照 |

解析时使用 `time` 字段；`tool/call.data.arguments` 是 JSON 字符串，需要二次解析。下列数字来自日志快照，不能替代新版本的真实平台检查。

## 主要观察

### 等待和平台启动占据长尾

在 `b2000b20` 中，step 的中位耗时约 12.7 秒，90 分位约 30.3 秒，最长约 305 秒。最长的两次等待来自 `wait_agent`（约 305 秒和 157 秒）；一次 `ctf_start_env` 约 96 秒。日志不能把这段时间全部归因于插件：前者是宿主等待策略，后者包含平台启动环境的时间。

这说明编排时应避免长时间无条件等待，并在启动环境期间给 agent 明确的进行中状态。它不能单凭这两份日志证明某个模型或平台版本的整体速度。

### 请求高峰

短时窗口内工具调用峰值约 60 次/分钟。旧版本面板和视图各自每 5 秒轮询一次 `/state`，一次快照会触发多次平台请求；工具调用和轮询叠加后可能造成会话 403。

当前版本已加入面板 TTL、single-flight、刷新下限和滚动刷新预算；赛事 7 的真实 smoke/e2e 及 macOS DSH 面板回执已通过。不同部署实例共用账号时仍需由部署层统一协调限流。

### 理论题调用次数符合任务量

一次旧会话中 `ctf_theory` 调用 107 次，其中 100 次是逐题作答，不能仅以调用次数判断为重复请求或异常。没有题目数量、答题状态和接口响应的联合证据时，不应把它列为性能缺陷。

### 环境失败后的行为

日志中 `ctf_start_env` 共 27 次：成功 20 次、撞配额 5 次、其他失败 2 次。撞配额分散在不同时间点，未看到同一题连续盲重试。该结论只适用于这两个历史会话。

### Agent 和工作区

旧会话出现过一次 teammate 名额不足。日志还显示题目目录和 writeup 曾落到 DSH profile 目录，而不是会话工作区；这与当时使用进程 cwd 和相对路径有关。当前代码以会话/调用上下文的工作目录为优先，macOS DSH 已完成实际安装和重启回执，Windows 路径仍待复验。

## 不足

- 没有旧版 0.1.0 的同赛事日志，无法做严格版本速度对比。
- 日志不包含完整的 teammate 生命周期、题型并发和平台服务端耗时。
- 本附录不保存本轮 Cookie 和原始响应；赛事字段、排名、理论题和环境接口的本轮回执请以 `docs/AUDIT.md` 与 `docs/RELEASE-1.0.9.md` 为准。

需要更新本报告时，先保存脱敏的原始 session，再记录 DSH 版本、赛事 ID、会话时区和验证命令；不要把 Cookie、完整请求头或私有题面提交到仓库。
